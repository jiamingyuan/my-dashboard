# my-dashboard V0.1 测试方案

> 状态：已于 2026-10-21 执行，结果见 test-results.md。以下保留适用场景、步骤和标准，不替代真实测试证据或用户验收。

## 测试依据与范围

- 依据 [需求验收标准](requirements.md#验收标准) 与 [执行方案](spec.md)，覆盖工程可运行、双主题、外壳样式、搜索空白占位、无模块范围、宿主导航和基础小屏操作。
- 桌面视觉参照现有 [晨间总览](https://www.figma.com/design/P2EfZNJYj2PsdZLmaMzHMN?node-id=14-266) 和 [夜间总览](https://www.figma.com/design/P2EfZNJYj2PsdZLmaMzHMN?node-id=4-86)。只比较本版保留的外壳，模块区域用本版 EmptyState 验收，不把差异全部当成视觉失败。
- 不验证业务模块、后端、身份认证、搜索功能、上线部署或插件协议，因为本版均不实现。

## 环境与前置条件

- 项目根目录运行；Node 24 LTS 与 npm，精确依赖以执行时实际 package-lock.json 为准。当前观察环境为 Node v24.20.0、npm 11.19.0，执行时重新记录。
- 先完成 spec 中工程、资源及交互实现，再安装 Playwright 所需 Chromium。不能把文档校验通过当成应用测试通过。
- 使用独立浏览器上下文隔离 localStorage；必要时在脚本加载前注入无效值或存储读写异常。测试数据不包含任何业务模块。
- 视口：1440 × 1000 为 Figma 视觉基准；1024 × 768 验证中等宽度；390 × 844 验证小屏。固定时间为 2026-10-20 12:00 Asia/Shanghai，仅用于截图与日期断言；另验证真实时间渲染格式。
- 使用可访问角色与名称定位实际控件，不依赖实现细节类名；视觉截图前等待本地字体和图标加载完成。浏览器记录 pageerror、控制台错误、失败资源和 API 请求。
- 网络不可用、浏览器未安装或资产缺失时如实标记对应验证未执行或失败，不伪造测试结果。日志和截图保存到被忽略的测试产物目录，文档只链接实际证据。

## 测试场景与步骤

### 工程与锁文件

1. 在工程就绪后运行 `npm ci`，确认唯一 npm 锁文件可还原依赖、没有覆盖 pjkp；记录实际 Node/npm 版本。
2. 运行 `npm run typecheck`、`npm run lint`、`npm run build`。预期全部退出码为 0，产生 dist，没有遗留模板计数器或 Vite / React 演示标志。
3. 运行 `npm run dev -- --host 127.0.0.1` 验证开发页，停止后运行 `npm run preview -- --host 127.0.0.1` 验证构建结果。预期可打开，静态资源正常，无 pageerror；不需要任何后端进程。

### 桌面双主题视觉与资产

1. 1440 × 1000 视口分别打开晨间和夜间总览，固定时间并等待 document.fonts.ready，截取完整页面。
2. 比较 sidebar 248、topbar 72、品牌、内容间距、圆角、主题开关及日期的位置。检查主要主题色、Noto Sans SC / Manrope 实际渲染字体和字重；不以 CSS 声明了字体就视为字体已加载。
3. 为每个可见静态 SVG 核对本地非空文件、来源图层、使用位置和实际渲染尺寸；浏览器无破损图片，代码无 Figma 临时资源 URL，无整页截图充当 UI。
4. 主内容仅为页面标题、欢迎区、单个无工具空状态和页脚；文字不裁切、不重叠，1440 视口无水平溢出。空状态和后续自适配作为 Agent 方案独立审阅。

### 主题状态与降级

1. 清空存储打开总览，预期为夜间，只有对应主题按钮 aria-pressed=true。
2. 点击“晨间”，预期 html 主题与所有可见面板、文字、图标同步改变，URL 不变；刷新后仍为晨间。再切回夜间验证对称行为。
3. 在首屏加载前注入合法晨间选择，预期首帧按晨间初始化；通过导航响应前暂停与首屏录制检查，不能只看加载后的最终截图判断无闪色。
4. 注入无效存储值，预期回退夜间。分别模拟读取失败、写入失败，预期页面仍可启动、仍可手动切换，无未捕获异常。写入失败不要求刷新后保留。
5. 通过 Tab 和 Enter / Space 切换主题，预期焦点可见、名称与选中状态正确；减少动画偏好下无不必要过渡。

### 搜索留白

1. 1440 视口取得保留占位和相邻控件的边界。相对 Topbar 的预期为：搜索占位 x=562、y=17、264 × 38；主题开关 x=842、y=16、152 × 40；日期 x=1010、y=24、142 × 24，允许 1 CSS 像素以内测量差。
2. 两个主题重复检查：占位透明且为空，没有输入框、搜索图标、提示文字、⌘ K、role=search 或搜索快捷键处理；Tab 不停在占位，点击留白不触发操作。
3. 在小屏确认占位按响应式方案隐藏且没有导致横向溢出；不能误把缩小后隐藏占位记成桌面占位丢失。

### 无模块范围检查

1. 可见导航只有“总览”；“我的工具”显示无工具提示。没有 AI 日报、背单词、media-keeper 的入口、卡片、计数、进度或操作按钮。
2. 主内容显示空状态，不出现学习词条、日报样例、媒体收藏或业务最近使用记录。框架页面不展示测试状态、技术栈卡片等用户未要求的内容。
3. 分别直接访问 `/ai-daily`、`/words`、`/media-keeper` 等非已注册地址，应落到通用 404，而非示例业务页面。检查路由和导航配置为空业务集合，不能只靠隐藏入口通过。
4. 观察网络，仅允许本地应用资源、字体和 SVG；无业务 API 调用、模拟接口、隐式登录请求或 Figma 临时资产请求。检查工程没有 src/modules 或业务样例数据文件。

### 小屏与可访问操作

1. 1024 × 768 视口中内容可用、顶栏不重叠；390 × 844 中 document.scrollWidth 不大于 viewport，页面可以自然滚动，主题控件可见。
2. 小屏按导航开关打开抽屉，预期 aria-expanded 状态正确，焦点进入导航，抽屉开启时背景内容不可交互且焦点不逃逸。
3. 按 Escape、点击遮罩、使用关闭按钮分别关闭，预期恢复触发按钮焦点和原滚动状态；点击“总览”返回并关闭抽屉。
4. 桌面不保留无响应的设置 / 个人菜单按钮；静态个人信息不冒充登录态。Tab 顺序与阅读顺序一致，原生链接和按钮有清晰名称。

### 宿主导航与文档

1. 直接打开 `/`、刷新、进入随机未知地址，预期总览正常、未知地址显示 404，点击“返回总览”可恢复外壳；主题选择保持一致。
2. 检查 README 的安装、dev、typecheck、lint、build、preview、test:e2e 命令与实际脚本匹配。执行 `npm run test:e2e`，预期上述有价值的行为断言通过；截图审阅结果单独记录。
3. README 说明未来修改 router 与 navigation 的真实位置，不声称已有业务模块协议；说明静态服务器需 SPA fallback，未实际部署不记成部署通过。

## 通过标准

- 所有本版必须场景执行并通过，检查命令退出码为 0；主题行为、存储异常、空状态、路由和小屏交互有实际证据。
- 双主题桌面截图完成核对，当前范围内的错误资源、字体、颜色、位移、重叠和溢出已修复；未知移动设计不伪称原稿精确复刻。
- 搜索占位与相邻尺寸满足上述基准；没有任何业务模块实现或业务 API 请求。
- 测试结果注明真实执行环境、命令、截图和限制，不将未执行记成通过。测试通过后仍须用户明确验收才能关闭版本。

## 未覆盖与待确认事项

- 当前已执行本版场景，证据见 test-results.md；后续实现变化应重新核对适用性，不能沿用过期结果。
- Playwright 自动回归以 Chromium 为最低范围；Safari / Firefox 的兼容性未承诺、须在未来明确范围后增加验证。
- 字体初次加载可能产生短暂排版变化；本版要求本地资源可加载并核对最终几何，主题首屏初始化另做检查。
- 小屏与空状态为 Agent 方案，用户可在交付时调整；自动测试不能替代主观 UI 审阅。
- 不覆盖生产托管、后端安全、账号与业务模块，因为本版没有这些实现。
