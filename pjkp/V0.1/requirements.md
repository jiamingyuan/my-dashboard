# my-dashboard V0.1 需求

## 版本目标

基于现有 Quiet Bronze Figma UI，建立 React + TypeScript + Vite 前端基础框架，供后续逐步接入工具。V0.1 只交付应用外壳，不加入任何业务模块。

来源：2026-10-20 用户要求“通过pjkp的plan模式，基于这套UI，先将前端框架搭建出来，但不加任何模块”，随后明确选择“V0.1：前端基础框架”。当时仅完成版本创建与 plan；2026-10-21 用户明确表示“那就开始执行吧”，授权按该方案搭建和验证。

## 范围与预期行为

### 本版范围

- 建立独立可运行、可构建的前端工程，保留现有 pjkp/ 文档。
- 延续设计稿的品牌、字体、配色、侧栏、顶栏、面包屑、页面标题及页脚；主内容区改为没有工具的空状态。
- 提供晨间 / 夜间切换；保留之前已经移除搜索框的决定，搜索位置仅为空白占位。
- 侧栏只有宿主“总览”入口，“我的工具”区域为空。AI 日报、背单词、media-keeper 均不注册、不展示入口或占位业务页面。
- 将应用布局、主题和基础展示组件分离，给后续接入工具保留扩展位置；此版不建设插件系统或模块 SDK。
- 提供启动、类型检查、代码检查、构建、预览说明及对应验证方案。

### 本版排除

不加入日报内容、单词学习、媒体收藏、示例工具卡片、业务统计、业务最近使用记录、模块路由、模块服务或模拟 API；不搭建后端、数据库、登录、权限、搜索、部署或发布流程。设计稿中的设置与个人下拉交互也不在本版实现；保留静态个人信息展示，不放置无响应的可点击入口。

### 规划采用的工作假设

以下为 Agent 在上述范围内选择的实施默认值，可在执行前或审阅时调整，未声称是用户逐项确认的需求：默认夜间模式，手动主题选择保存在本地；以桌面设计为视觉基准，并提供小屏基础适配；空状态文案为“还没有添加工具”，无添加工具按钮；日期使用浏览器本地日期，个人信息沿用稿中 Jiaming 的静态展示，不代表登录态。

## 验收标准

下列条目是对用户范围的可验证转译，最终验收仍由用户完成。

1. 工程可以按 README 安装和启动；类型检查、lint、生产构建均通过，预览可打开。
2. 在 1440 × 1000 桌面视口，应用外壳的侧栏宽度、顶栏高度、品牌、配色、字体和留白与当前设计一致；模块相关画面明确按本版范围替换为空状态。
3. 晨间和夜间均能正常显示；切换主题不改变当前页面，刷新恢复手动选择，本地存储不可用或值无效时仍可使用默认主题并正常切换。
4. 桌面搜索占位保持 264 × 38，没有输入框、图标、文字、快捷键、点击区域或 Tab 焦点；右侧主题开关和日期保持设计中的位置关系。
5. 主界面和可访问路由均没有业务模块、假数据或业务 API 请求；“我的工具”只有空状态提示。
6. 基础布局能在 1024 和 390 像素宽度正常使用；页面无水平溢出。主题控件和小屏导航可通过键盘操作，焦点可见，抽屉可关闭并恢复焦点。
7. 未知 URL 显示宿主 404，可回总览；README 说明后续新增页面与导航的位置及 SPA 静态托管回退要求。

## 已确认决定与开放问题

### 用户已确认

- 项目与前端技术栈：my-dashboard，React + TypeScript + Vite，来源为本对话前序选型。
- UI 来源：现有 Figma 晨间 / 夜间双主题，以及移除搜索框但保留位置的修订。
- 当前范围：只搭建前端框架，不加任何模块；先完成 pjkp plan，再于 2026-10-21 依据用户授权进入执行与验证。
- 版本名：V0.1，来源为本轮版本号问题的用户回复。

### 开放问题与影响

- 后端、模块接入方式、登录与部署均留给后续需求，不阻塞本版前端外壳规划。
- 移动端与空状态没有独立 Figma 画面，按工作假设实施，交付时单独展示，不能宣称逐像素复刻了不存在的设计稿。
- 依赖精确版本已在执行时核验并通过 package-lock.json 固定，实际入口见 README 和 package.json。
- 已有前端源码；当前不是 Git 仓库，未初始化远程仓库或创建 PR。

## 版本结果

2026-10-21 已实现前端基础框架；锁文件重装、类型检查、lint、生产构建及 11 项 Chromium 回归通过，详见 [测试结果](test-results.md)。应用含双主题、搜索留白、无工具空状态、404 与小屏导航，没有任何业务模块。尚未取得用户验收，版本不关闭，也未部署。
