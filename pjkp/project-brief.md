# my-dashboard 项目简介

更新：2026-10-26。当前版本为 V0.3；核对了本版源码、配置和现有运行容器。

## 项目定位与长期方向

将用户自己开发的工具集中到一个网站，通过 sidebar 选择和使用各模块。用户于 2026-10-23 明确优先接入 media-keeper，前端融入 my-dashboard；本轮要求在 Figma 中移除 AI 日报、背单词的设计，呈现 media-keeper 的预期样式。用户随后授权开发，media-keeper 业务前端已作为独立远程模块接入。

来源：2026-10-20 用户要求“这个项目是一个包含前后端的网站，能够将我做的一些工具通过模块化的方式接进来”。前端随后由用户从 Vue 3 改为 React，沿用 TypeScript 与 Vite。

## 当前能力

| 能力 | 现状 |
| --- | --- |
| 前端外壳 | V0.1 已实现侧栏、顶栏、总览、通用 404、小屏导航与无工具空状态 |
| 晨间 / 夜间 | 同一套组件切换语义色，手动选择本地保存，存储异常仍可切换 |
| 全站字体 | 2026-10-23 按用户要求改为系统 PingFang SC，中英文、品牌、日期与控件统一；未安装时回退 sans-serif，已移除旧 Web 字体 |
| 搜索位置 | 保留桌面透明留白，没有搜索输入、快捷键或搜索能力 |
| 模块化接入 | V0.2 已实现 Module Federation；读取运行时 JSON 清单，生成菜单和模块路由，按需加载远程 React 组件 |
| 模块协作 | 宿主传递主题、模块根路径、子路径、查询串与导航函数；远程加载或渲染失败时提供提示和重试 |
| 业务工具 | 正式清单已登记 media-keeper，业务源码留在其独立仓库；AI 日报和背单词未接入 |
| 后端与账户 | 宿主尚无后端、数据库接口、登录或权限功能；本机 MySQL 服务的存在不代表项目已使用数据库 |
| 运行 | 本机 Node.js 开发，构建后由独立 Nginx 容器在 http://localhost:8080 提供静态页面，无 Volume |

V0.1、V0.2 与 V0.3 的实际结果、用户来源和验证限制分别见 [V0.1 迭代记录](V0.1/iteration.md)、[V0.2 迭代记录](V0.2/iteration.md)、[V0.3 迭代记录](V0.3/iteration.md)。测试通过和继续迭代均不补写为用户验收。

## 已确认的方向与尚未确定的范围

- 用户希望不同项目定义的 UI 能接入宿主页；当前支持独立构建、独立部署的远程 React 组件。宿主不需要包含各工具源码；接入方法见 [模块说明](../docs/module-integration-guide.md)。
- Figma 晨间 / 夜间参考保留在 [设计文件](https://www.figma.com/design/P2EfZNJYj2PsdZLmaMzHMN)。稿内业务内容与数字仅为设计示例。
- media-keeper 已提供独立 NestJS 只读 API 与 MySQL 资料库，通过同域代理供模块调用。宿主账户、其他模块后端、登录权限、公网部署、域名及 HTTPS 尚未确定；没有自行排入后续版本。
- 优先接入项目已确定为 media-keeper；已有 Figma 设计覆盖 Media 工具页和资料详情的晨间 / 夜间两套画面，内容为示例；总览暂不放 media-keeper。工具页仅保留关键词与发布日期五档预设，来源与作者暂不提供筛选；类型图标与名称位于标题前，copied_lark_link 非空时在标题后显示飞书转存标签，摘要采用无内嵌背景的完整正文段落。用户已授权开发，实际前端已在本机通过 /media-keeper/ 资源和 API 路径接入；当前已有能力由用户于 2026-10-26 指定归为 V0.3；后续公网部署范围尚未指定。
