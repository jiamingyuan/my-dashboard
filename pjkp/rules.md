# my-dashboard 原则与边界

## 项目原则

- 项目名称为 `my-dashboard`，目标是包含前端和后端的网站。
- 网站支持模块化接入用户自己做的工具，sidebar 提供工具入口。
- 上述两项方向来源：2026-10-20 用户在当前对话的项目初始化要求。
- 前端采用 React + TypeScript + Vite。来源：2026-10-20 用户明确要求“这里改成react吧”，沿用已确定的 TypeScript 与 Vite；V0.1 按已形成并获执行授权的方案使用 React Router、CSS Modules 和 React Context，未引入业务 UI 库。

## 执行边界

- 当前已执行项目文档初始化、技术选型记录与 UI 设计；V0.1 已依据 2026-10-21 用户“那就开始执行吧”的授权完成前端实现与本版验证。
- 用户于 2026-10-20 指定 V0.1：先基于现有 UI 搭建前端框架，不加任何模块，并要求使用 pjkp plan。当前范围不包含后端、业务模块或部署；用户尚未验收，版本不关闭。
- 用户于 2026-10-21 追加授权本机容器运行：名称固定为 my-dashboard，使用已有 debian:trixie，将项目放入并启动。该操作独立于原 V0.1 的前端功能范围，不据此增加后端、模块或公网发布，也不代替用户验收。

## 专项约定

- 用户于 2026-10-21 明确要求后续直接在 my-dashboard 容器开发，并授权删除本地 ai-infa 里的项目。唯一工作副本为 `/app/my-dashboard`，持久化卷为 `my-dashboard-project`；源码读写、依赖安装、构建、测试及 pjkp 更新在容器中进行。宿主仅保留容器入口说明，不重建本地源码副本。 宿主目录拼写已由 ai-infa 更正为 ai-infra；改名后残留的 my-dashboard 副本于后续复查中核对、归档新增记录并删除。

- 涉及飞书 / Lark 操作时，优先使用本机 `lark-cli`，先检查其支持命令并复用现有登录状态；只有 CLI 不支持或不可用时再考虑连接器或浏览器等方式。来源：用户在本轮提供的 AGENTS.md 指令。
- 其他项目专项约定待用户提出。
